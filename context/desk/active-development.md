Effective 17 September 2026. Sayuj explicitly requested an automated system that goes directly to Claude to develop the projects. It does not change the charter, protected policy, financial limits or permissions for previously rejected transfers.

The existing `partnership-desk-check` heartbeat coordinates the work every 30 minutes when this Mac and the required sessions are available. A scheduled prompt is an execution instruction, not proof that a future run succeeded. Every run must leave evidence in the queue/outbox and the canonical handoff.

## Select and do work

1. Check STOP with `os.path.lexists`, then current policy/approval, original project instructions, canonical handoff, Git state and relevant Claude conversation. Read the latest messages, not merely the last messages visible in a partially loaded chat.
2. Run the existing local `desk.py tick` without notification flags. A transient approval-service transport failure is different from a policy rejection: retain the exact result and follow its permitted recovery instructions. The 17 September local check succeeded; the 14 September recovery hold is no longer current. A genuine denial is never permission to change tools or destinations to evade it.
3. Execute an eligible queued task. When none exists, inspect the nine-project catalogue and current handoffs and enqueue one concrete, authorized next step. Start with IBKR because Sayuj named it. Record the project, source evidence, deliverable, acceptance checks, current executor, expected return/time-to-first-dollar (null when unknown), and stop condition. Choose another eligible project if one project is blocked. Do not invent a financial ranking or repeat completed prototypes.
4. Claim immediately before work. Use a separate `desk/<task-id>` worktree, one writer, and the current desk controls. Limit each unit to 15 minutes including verification, commit and accounting; reserve the last three minutes for closure. Respect parent time/cash allocation, two workers, eight Claude turns and maximum family depth three. A date change, empty queue or new heartbeat does not reset an exhausted family. New independent work must have a distinct evidenced purpose, not conceal a retry.
5. Obtain a concrete contribution from Claude: a scoped design, reference implementation, diagnosis or independent review. Execute the authorized build or verification in Codex, then have the other partner review the exact change where the required evidence can be supplied. If a partner has no credits/access, continue independent eligible work with the available partner and retain the review request. Never label that work jointly approved.
6. Finish or block through the desk with actual evidence, elapsed time and accounting; append the canonical handoff. Queue a justified successor only within the same family's remaining controls. At final depth, report the outcome and stop that family.

## Direct Claude routes

- **Native Claude reviews:** use the existing `desk.py run TASK_ID` adapter for its supported prompt-only research/review jobs. It verifies native Pro/Max auth and matching fresh evidence that usage credits are off. It currently has no tools and cannot edit the repository. Do not pretend it is a file-writing worker.
- **Existing project conversation:** the newly requested direct development collaboration may use Computer Use for one bounded assignment based on the conversation's existing context, or an authorized supplied review packet. Verify the exact project/conversation, preserve drafts and active responses, check STOP before typing/sending, and verify signed-in existing-plan access with usage credits off within one hour. Keep an immutable message, stable ID and receipt; verify the sent message and the actual returned work product. Do not send an acknowledgement-only loop. Requests must bound tool use, turns and scope; no broker/service/financial/account action is authorized by a chat assignment.
- **Changes from Claude:** a web response or patch is a candidate artifact. Astra inspects it, tests it locally where authorized, and records the exact source/version and verdict. Any later changed commit needs another review. A cloud chat cannot read Mac paths by implication.

No broad provider fallback, credential proxy, API billing, subscription changes, quota bypass or permission-prompt approval. A rejected private packet remains pending for the required approval; a different destination or paraphrase is not a workaround. Unrelated safe project work can continue.

It adds no second lifecycle and changes no protected policy or approval record. Each heartbeat run should now:

0. A launch agent runs `/usr/bin/python3 /Users/sayuj/soojos/tools/soojos-desk/desk_beat.py` every 5 minutes (gate, tick, inbox sync with Haiku routing, dispatch of `auto_dispatch` tasks, board; log in ~/.soojos/desk/beat.log). Your beat still starts with the gate: run `/usr/bin/python3 /Users/sayuj/soojos/tools/soojos-desk/heartbeat_gate.py` before any model turn. `UNCHANGED` (exit 0) ends the beat with no entry; `ATTENTION` names the reasons (decision 0007: 128 of 158 entries from 19–24 September were unchanged checkpoints).
1. Call `desk_status` first. If `stop_present` is true, stop; report nothing else. Note `billing_evidence`: worker launches are refused unless `~/.soojos/desk/subscription-billing.json` (Claude) or `codex-billing.json` (Codex) shows usage credits disabled, verified within the last hour, for the organization the CLI is signed into.
2. Call `inbox_sync` so Sayuj's plain-language sections in `context/desk/INBOX.md` become validated queue entries (the outcome is written back under each heading), then `desk_tick` to apply persisted completions and block overdue running tasks with desk accounting, then `queue_list(status="running")` and `run_status` to see work still in flight. 3. For an eligible queued task, call `run_task(id, background=true)`. It claims through the desk, reserves one run identity under the desk lock, isolates in `.worktrees/task-<id>` on branch `desk/<id>`, bounds the worker by the smaller of the budget and the persisted deadline minus a closure reserve, verifies zero cash, runs the assignee, and finishes through `Desk.finish` or `Desk.block` with elapsed time and tokens. Headless `codex exec` can call the read-only tools (`desk_status`, `queue_list`, `outbox_read`, `git_status`, `run_status`) without approval; the mutating tools need the interactive Codex app or Claude Code as the caller. Nothing in this server merges, pushes, edits credentials, cloud instructions, the charter or policy files.
