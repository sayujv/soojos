## Design checks

Three approaches were considered: full parallel products would invent missing choices; waiting for perfect source recovery everywhere would postpone useful work; isolated offline slices preserve forward progress and current authority. The last approach is selected. The main failure modes are duplicating a newer build, mistaking synthetic test output for demand, and accidentally invoking live behavior through old entrypoints. Isolation, explicit source questions and no target imports/entrypoints address these.

The load-bearing commercial assumption is demand: it is unverified for these slices. This prevents a launch or capital recommendation, not creation of a reversible artifact. No financial return is promised. The cheapest functional test is the FIFO tracker’s expiry/date/CSV boundary fixtures; real demand remains a separate experiment.
