## Practical research rule for both assistants

When an active task reveals a missing capability, first inspect existing skills, CLIs and MCP tools. Search recent official documentation, release notes and the MCP Registry; use Scrapling selectors for focused source retrieval. Record the release/publication date, the problem solved, overlap with current tools, auth and likely costs, and one small test that would demonstrate value. Apply the September 7 local/open-source/no-provider-proxy preference before ranking tools, and label cloud-service exceptions explicitly. Prefer an existing CLI over an equivalent MCP service. Record selected candidates in the shared project or system research log so the other assistant can see the decision. Installation and account connection should follow the user's authorized scope; discovery alone should not trigger mass installation. Preserve the September 21 ccusage review and its conditional RTK decision rather than reopening it early.

Do not add a second persistent memory database or an autonomous agent swarm solely to switch credit providers. Shared files, Git state, explicit ownership of concurrent work, and current handoff records directly address the continuity requirement with fewer moving parts. No tools were installed or configured during this research.
